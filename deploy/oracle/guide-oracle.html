VELA · cerveau 24/7

Mettre le relais IA en ligne, gratuitement

On déménage ton tunnel Cloudflare existant sur une VM Oracle « Always Free ». Le réseau de la VM n'est pas filtré comme ton WiFi : le tunnel tiendra enfin, en permanence, et sans ouvrir un seul port entrant.

📱 App client→ relais.velaglass.ca→ ☁️ tunnel→ 🖥️ VM Oracle→ uvicorn :8100

0

Avant de commencer sur ton PC — carte, secrets frais, clé SSH, paquet de code

  1. Une carte (crédit ou débit). Oracle fait une empreinte temporaire de ~1 $ pour vérifier l'identité ; rien n'est débité tant que tu ne passes pas volontairement en payant.
  2. Rafraîchis les secrets qui ont pu fuiter. Si une clé a déjà été collée dans une conversation (ex. la clé Stripe sk_live), révoque-la dans Stripe (Développeurs › Clés API › « Roll key ») et crée-en une neuve — idéalement restreinte (rk_live). Seules des clés fraîches iront sur la VM.
  3. Génère une clé SSH, puis affiche la clé publique à copier :
ssh-keygen -t ed25519 -C "iris-vm"
Get-Content $HOME\.ssh\id_ed25519.pub

Fabrique le paquet de code à envoyer (sans secrets ni venvs) :

powershell -ExecutionPolicy Bypass -File C:\Users\migue\Downloads\startup\iris\deploy\oracle\faire-bundle.ps1

→ crée C:\Users\migue\Downloads\vela-vm-bundle.zip

1

Créer le compte Oracle + la VM Always Free · Ubuntu · ARM

  1. oracle.com/cloud/free › Start for free. Courriel, vérification, carte (empreinte ~1 $).
  2. Région d'accueil : choisis une région canadienne — Canada Southeast (Montreal) ou Canada Central (Toronto). ⚠️ Ce choix est définitif.
  3. Console › ☰ › Compute › Instances › Create instance :
    • Image : Canonical Ubuntu 24.04 (ou 22.04).
    • Shape : Change shape › Ampere (ARM) › VM.Standard.A1.Flex › 1 OCPU / 6 Go. Assez pour tes deux serveurs, et une petite VM est moins susceptible d'être jugée « inactive » (voir ci-dessous). Max gratuit : 2 OCPU / 12 Go.
    • Clé SSH : Paste public keys › colle le contenu de id_ed25519.pub.
    • Laisse le réseau par défaut. Create.
  4. Note l'IP publique de l'instance.

⚠️ « Out of host capacity » — l'ARM gratuit est souvent indisponible. Réessaie plus tard, change d'Availability Domain, ou prends en secours une micro AMD VM.Standard.E2.1.Micro (x86, 1 Go — marche aussi).

⚠️ Récupération des instances inactives — Oracle peut arrêter une VM ARM dont l'usage reste < 20 % sur 7 jours. Parades : garder une petite VM + le ping de la Phase 5 (génère du trafic). En dernier recours, passer en Pay As You Go (reste gratuit dans les limites, plus aucune récupération) — avec une alerte de budget.

2

Connexion + utilisateur de service + sécurité l'utilisateur Ubuntu par défaut est « ubuntu »

Connecte-toi (remplace IP_PUBLIQUE) :

ssh -i $HOME\.ssh\id_ed25519 ubuntu@IP_PUBLIQUE

Sur la VM — mises à jour, outils, utilisateur de service, sécurité automatique :

sudo apt update && sudo apt -y upgrade
sudo apt -y install python3-venv python3-pip curl unattended-upgrades fail2ban
sudo adduser --system --group --home /home/vela --shell /bin/bash vela
sudo dpkg-reconfigure --priority=low unattended-upgrades   # répondre « Oui »
sudo systemctl enable --now fail2ban

Durcir SSH — garde une 2ᵉ fenêtre SSH ouverte et teste une nouvelle connexion avant de fermer celle-ci, sinon tu risques de te verrouiller dehors. Sur Ubuntu 24.04 il faut modifier deux fichiers (le second réactive le mot de passe en douce).

sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config.d/50-cloud-init.conf 2>/dev/null || true
sudo sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
sudo sshd -t && sudo systemctl restart ssh

On n'ouvre aucun port entrant (ni 80/443, ni 8100/8110) : le tunnel sort de la VM. On ne touche ni les Security Lists du VCN, ni iptables. N'installe pas UFW (conflit avec l'iptables d'Oracle → risque de couper SSH).

3

Envoyer le code + les secrets clés fraîches uniquement

Le code — depuis PowerShell (PC) :

scp -i $HOME\.ssh\id_ed25519 "$HOME\Downloads\vela-vm-bundle.zip" ubuntu@IP_PUBLIQUE:/tmp/

Sur la VM :

sudo mkdir -p /home/vela/iris
sudo unzip /tmp/vela-vm-bundle.zip -d /home/vela/iris
sudo chown -R vela:vela /home/vela/iris

Les secrets du relais — /home/vela/iris/serveur/.env, format strict CLE=valeur (pas de guillemets, pas d'espace autour du =) :

sudo -u vela nano /home/vela/iris/serveur/.env
VELA_OPENROUTER_KEY=sk-or-...
VELA_ANTHROPIC_KEY=sk-ant-...
VELA_SECRET=un-secret-long-au-hasard
VELA_ELEVENLABS_KEY=...
VELA_LICENCES_URL=http://127.0.0.1:8110

Les secrets des licences — /home/vela/iris/server/.env, repars de server/.env.exemple avec la clé Stripe restreinte fraîche et/ou PayPal. Puis verrouille :

sudo chown vela:vela /home/vela/iris/serveur/.env /home/vela/iris/server/.env
sudo chmod 600      /home/vela/iris/serveur/.env /home/vela/iris/server/.env

Jamais l'ancienne clé sk_live compromise, même « juste pour tester ».

4

Installer + l'identité du tunnel installer.sh fait le gros du travail

Lance l'installateur (en tant que ubuntu) : Python, venvs, cloudflared, services systemd :

chmod +x /home/vela/iris/deploy/oracle/installer.sh
/home/vela/iris/deploy/oracle/installer.sh

Dépose l'identité du tunnel — depuis le PC, envoie seulement le fichier <id>.json :

scp -i $HOME\.ssh\id_ed25519 "$HOME\.cloudflared\3b543fb7-c1cc-4967-a9c4-a76b9afb246b.json" ubuntu@IP_PUBLIQUE:/tmp/

Sur la VM :

sudo -u vela mkdir -p /home/vela/.cloudflared
sudo cp /home/vela/iris/deploy/oracle/config.yml /home/vela/.cloudflared/config.yml
sudo mv /tmp/3b543fb7-c1cc-4967-a9c4-a76b9afb246b.json /home/vela/.cloudflared/
sudo chown -R vela:vela /home/vela/.cloudflared
sudo chmod 600 /home/vela/.cloudflared/*

N'envoie JAMAIS cert.pem sur la VM. Il contrôle tous tes tunnels (valable ~10 ans). Le <id>.json suffit à faire tourner celui-ci. Garde cert.pem sur ton PC uniquement.

5

Bascule, démarrage, vérification un seul tunnel actif à la fois

1. Coupe d'abord le tunnel du PC — sinon Cloudflare répartit le trafic au hasard entre PC et VM. Sur le PC (PowerShell) :

Get-Process cloudflared -ErrorAction SilentlyContinue | Stop-Process -Force
Remove-Item "$HOME\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\lancer-tunnel.vbs" -ErrorAction SilentlyContinue

2. Démarre tout sur la VM :

sudo systemctl enable --now vela-relais vela-licences cloudflared

3. Vérifie pour de vrai (le local qui répond ne prouve pas que le public marche) :

systemctl status vela-relais vela-licences cloudflared --no-pager
curl -s http://127.0.0.1:8100/sante ; echo
journalctl -u cloudflared -e --no-pager | tail

Puis depuis ton téléphone / un autre réseau, ouvre :

https://relais.velaglass.ca/sante
https://licences.velaglass.ca/sante

Erreur DNS/502 alors que le local répond ? Les routes du tunnel manquent. Depuis le PC (il a cert.pem) :

cloudflared tunnel route dns vela-relais relais.velaglass.ca
cloudflared tunnel route dns vela-relais licences.velaglass.ca

4. Preuve du 24/7 — redémarre la VM et vérifie que tout remonte seul :

sudo reboot
# reconnecte-toi ~1 min plus tard, puis :
systemctl is-active vela-relais vela-licences cloudflared

5. Garde la VM éveillée — crée un moniteur gratuit UptimeRobot qui frappe https://relais.velaglass.ca/sante toutes les 5 min. Ça évite la mise en veille et ça confirme que le brain est vivant.

Priorité = le relais. C'est lui que l'app des clients appelle pour l'IA. Le serveur de licences ne sert vraiment qu'une fois les paiements configurés — quand ce sera le cas, mets IRIS_ENV=production dans server/.env (en production, PayPal doit être configuré pour que le serveur démarre).

Référence complète et scripts : deploy/oracle/ dans le dépôt IRIS (GUIDE-ORACLE.md, installer.sh, faire-bundle.ps1, les 3 .service, config.yml).
